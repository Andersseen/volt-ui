## Release blocker (external, not a repository defect)

The 404 hit the **first** package (`@voltui/components`) as well as `@voltui/cli`, so it is not specific to the CLI. For an existing public scoped
package, npm answers `PUT` with 404 when the credential is not allowed to write to it (expired, revoked or wrong-scope token). `scripts/release.mjs`,
`release.yml` and the `publish:*` scripts are unchanged since 1.3.3 (published 2026-10-19 with the same flow). Nothing in the repository was changed:
swapping the authentication for another mechanism would only hide the problem.

**Maintainer action:** create a new npm automation / granular token with read-write on `@voltui/components`, `@voltui/cli`, `@voltui/agent`
that bypasses 2FA, store it as the repository secret `NPM_TOKEN`, then re-run the `Release` workflow (`workflow_dispatch`) on `main`; the script
is idempotent and publishes what is new on npm. The local environment is not logged in to npm (`npm whoami` → 401), so the token and the scope
permissions could not be inspected from here, and no secret was read or printed.

## Quartz 0.16.0 findings (read from the published tarball, not from Quartz `main`)

| Finding                                                                                                                                                                   | Consequence in Volt                                                                                                                                                                                                                                                |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `TabDirective`, `TabPanelDirective`, `AccordionItemDirective` build ids from **module-level counters** (`qz-tab-N`, `qz-tab-panel-N`, `qz-accordion-trigger-N`).          | The ids are the `aria-controls` / `aria-labelledby` targets, so they cannot be dropped. The wrappers assign per-application ids to the directives' `id` / `panelId` fields in their constructors (`replaceQuartzIds`), before registration and before any binding. |
| `TabsDirective.value` defaults to `null` and **writes the first tab's value** when a tab registers; on removal of the selected tab it writes the first remaining tab.     | ng-primitives only _shows_ the first tab (value stays undefined, nothing emitted). `VoltTabs` owns `value`; Quartz's value reaches the model only after a user click/keyboard move.                                                                                |
| `activationMode` is a signal **input** (`automatic` / `manual`). A host directive input cannot be bound from the host component's own host bindings (`NG0303`, verified). | Quartz always runs `automatic`; with `activateOnFocus` off `VoltTabs` restores the selection in the same keydown (before rendering).                                                                                                                               |
| `AccordionDirective.type` has **no default**; a single, non-collapsible accordion with `value === null` **opens the first item** on registration.                         | `type` defaults to `'single'` in Volt and is forwarded; Volt hands Quartz a value no item has (`NONE`) for "nothing open", so nothing opens and nothing is emitted.                                                                                                |
| A closed accordion panel gets `hidden` (`display: none`).                                                                                                                 | That cannot animate Volt's grid-row transition. The wrapper removes `hidden` after Quartz's binding and closes with `visibility: hidden` (delayed by the transition), which leaves the Tab order and the a11y tree.                                                |
| Accordion triggers use a roving `tabindex` (one Tab stop).                                                                                                                | ng-primitives (Volt contract): every trigger is a Tab stop. `tabindex` is rewritten after Quartz's binding; arrows/Home/End still work.                                                                                                                            |
| Focus recovery when a focused accordion trigger is removed **is present in 0.16.0** (`unregisterItem` → `focusSafely`).                                                   | Tested (`disclosure-quartz.spec.ts`). The Quartz 0.17+ changes are not needed for this contract.                                                                                                                                                                   |
| Peers `@angular/* ^21.0.0`.                                                                                                                                               | Angular 22 still needs `--legacy-peer-deps`; the consumer script reports the peer gap.                                                                                                                                                                             |

Upstream blockers (recorded, not worked around by forking): application-scoped id generator, widened Angular peers, an `activationMode`-style
setter that is not an input. All three are neutralised at the Volt boundary and verified.

## Decisions

1. Same architecture as v1.4/v1.5: `packages/volt/src/lib/quartz/{tabs,accordion}/`, exported from `quartz-api.ts`, no third backend, no adapter framework.
2. **Volt owns `value`** in both families. It is written into Quartz by an effect; Quartz's value reaches the model only from the user's events (`userSelected`, `onKeydown`, `userToggled`), and a returning part restores Volt's value (`tabRegistered`, `itemRegistered`).
3. Styling hooks: `data-state="active|inactive"` (Tabs) and `data-open` / `data-closed` / `data-disabled` (Accordion) are written by the wrappers; Volt CSS contains no `data-qz-*` selector.
4. Shared contract: `testing/disclosure-contract.ts` (Tabs 12 tests, Accordion 11 per engine) run against both engines by `ngp-and-quartz-disclosure.spec.ts`; Quartz-only exceptions in `disclosure-quartz.spec.ts`.
5. `quartz-ids.ts` gains `replaceQuartzIds`; no new helper file, so the CLI copy list is unchanged apart from the new component folders.

## Known differences (intentional, documented, tested)

See `docs/headless-backends.md` → "Known differences". In short: Enter/Space on a manual-activation tab (Quartz yes, ng-primitives no), RTL arrows (Quartz mirrors),
no dangling `aria-controls` (Quartz), `aria-disabled` on the one open non-collapsible accordion item (Quartz, per WAI-ARIA), arrow-key navigation and focus recovery in the accordion (Quartz only),
and `value` reset to `undefined` / unknown tab value (ng-primitives falls back to the first tab, Quartz keeps the current selection or none).
