## Release blocker (external, unchanged)

Third consecutive release run on `main` fails the same way: the build and `npm publish` start, and the **first** package (`@voltui/components@1.4.0`) answers
`PUT` with 404. For an existing public scoped package that means the credential in `NPM_TOKEN` may not write to it (expired, revoked or wrong-scope token). `scripts/release.mjs`,
`release.yml` and the `publish:*` scripts are unchanged since 1.3.3 (published 2026-10-19 with the same flow), so this is not a repository defect and nothing was changed. The local machine is not
logged in to npm (`npm whoami` → 401); the token and its scope could not be inspected and no secret was read or printed.

**Maintainer action:** create an npm automation / granular token with read-write on `@voltui/components`, `@voltui/cli`, `@voltui/agent` that bypasses 2FA, store it as the
repository secret `NPM_TOKEN`, then re-run the `Release` workflow on `main` (it is idempotent and publishes what is new). 1.4.0 must go out first; this work is the content of a later minor.

## Quartz 0.16.0 findings (read from the published tarball, not from Quartz `main`)

| Finding                                                                                                                                                                      | Consequence in Volt                                                                                                                                                                                          |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `ListboxDirective.value` is `T \| T[]`, `null` when empty; `multiple` is a boolean signal **input**. Volt's `mode` is `'single' \| 'multiple'` and `value` is always `T[]`.  | `VoltListbox` maps shapes at the boundary; the directive's `multiple` field is replaced by a signal derived from `mode` (`overrideQuartzInput`), since a host directive input cannot be bound from the host. |
| `ListboxOptionDirective.id` and `ListboxGroupDirective.labelId` come from **module-level counters**; the directive registers the first enabled option as active on its own.  | Option and header ids are counted per application (`VoltQuartzIds`); a supplied `id` wins. A bound `[id]` re-registers the option under its id in `ngOnInit`.                                                |
| Quartz's group directive always points `aria-labelledby` at its label. Volt's header is optional and may sit outside a section.                                              | `VoltListboxSection` / `VoltListboxHeader` keep the reference themselves, so nothing dangles.                                                                                                                |
| `NgpListboxTrigger` binds nothing (verified in ng-primitives 0.131).                                                                                                         | `VoltListboxTrigger` is the same empty marker on Quartz — not a fake: there is no behaviour to port.                                                                                                         |
| `SelectDirective` takes the popup template from `content` (input) or a `qzSelectContent` **content child of the host**; it needs to be on the host so options can inject it. | `VoltSelect` uses it as a host directive and overrides `content` with its own `ng-template`.                                                                                                                 |
| `OverlayService` positions the **first element** of the template and sets its `width` to the anchor's; the wrapper is `position: fixed`; no `container` option.              | `volt-select-content` is the panel and the `listbox`. `container`, `scrollToOption`, `allOptions` are **absent** from the Quartz `VoltSelect` (compile error, not silent), documented.                       |
| `SelectTriggerDirective` has no `role`; trigger id comes from a module-level counter; the popup is named from the trigger.                                                   | Wrapper adds `role="combobox"` and a native `disabled`, gives the trigger an application-scoped id.                                                                                                          |
| `valueChangeCommitted` / `valuesChangeCommitted` fire once per genuine user change, never for programmatic writes.                                                           | They are the only path into Volt's `value` and Angular Forms; no echo.                                                                                                                                       |
| The overlay mounts the popup and positions it one animation frame later.                                                                                                     | Documented as an upstream constraint; the browser suite samples after the frame.                                                                                                                             |
| Peers `@angular/* ^21.0.0`.                                                                                                                                                  | Angular 22 still needs `--legacy-peer-deps`; the consumer script reports the peer gap separately from runtime results.                                                                                       |

## Decisions

1. Same architecture as v1.4–v1.6: `packages/volt/src/lib/quartz/{listbox,select}/`, exported from `quartz-api.ts`, no third backend, no adapter framework, no private Quartz imports.
2. **Volt owns `value`** in both families; Quartz's value reaches the model only from `*Committed` outputs.
3. Styling hooks: `data-selected` / `data-active` / `data-disabled` (+ `data-open`, `data-multiple`, `data-placeholder` on the Select trigger) are written by the wrappers; Volt CSS has no `data-qz-*`.
4. Shared contract: `testing/selection-contract.ts` (Listbox and Select) runs against both engines through `ngp-and-quartz-selection.spec.ts`; Quartz-only exceptions in `selection-quartz.spec.ts`; SSR in `selection-ssr.spec.ts`; DOM and public-API differential in `backend-parity-selection.spec.ts`.
5. `VoltNativeSelect` is a native `<select>`; it is not part of this migration and stays default-only.
6. `quartz-ids.ts` gains `overrideQuartzInput`; `replaceQuartzIds` now takes any fields (`id`, `panelId`, `labelId`).

## Known differences (intentional, documented, tested)

See `docs/headless-backends.md` → "Known differences". In short: Quartz moves DOM focus into the Select popup and back to the trigger (ng-primitives does not restore focus), so the active option is highlighted by
`focus:`; Quartz writes `aria-disabled` on items so `aria-disabled:opacity-50` dims them (ng-primitives never writes it); an empty `multiple` Select shows its placeholder; the popup is positioned one frame after it mounts;
Listbox exposes `aria-orientation` and an active descendant before focus.
