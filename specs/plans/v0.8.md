# Plan v0.8.0 — Theme System & Docs Completeness

**Status:** not started
**Entry state:** v0.7.0 released (component list for v1 is final; nothing experimental)
**Goal:** the theme system is audited and documented (SDD.md §12.5) and the docs site is
complete for every shipped component (SDD.md §12.4). After this minor, only
distribution/API-freeze work remains.

---

## Context primer (replaces repo analysis — trust this, verify cheaply)

- Theme architecture (SDD.md §6): source tokens `--volt-*` in
  `projects/volt/src/themes/core.css` + preset files; mapped to Tailwind v4 via
  `@theme inline`; semantic vars `--background`, `--foreground`, `--primary`,
  `--destructive`, `--success`, `--warning`, `--error`, `--info`, etc.
  Components use Tailwind utilities (`bg-primary`), never raw `var()`.
- Presets: colors `volt | ember | sage | dusk | glacier` × styles
  `sharp | soft | brutal | ghost | retro` × light/dark = 50 combinations.
  Applied via `data-color` / `data-style` attributes + `.dark` class on the document
  element; runtime API `provideVoltTheme()` / `applyVoltTheme()` in the theme component
  (`projects/volt/src/lib/components/theme/`).
- Consumers import `@voltui/components/themes.css` (exported from
  `projects/volt/package.json`).
- Docs app: AnalogJS, pages in `src/app/pages/`; component demos at
  `(components-docs)/docs/components/<name>.page.ts`; getting-started content at
  `(getting-started)/docs/`; snippets in `src/app/lib/snippets/{index,usage}.ts`.
- Deploy: Cloudflare Pages, output `dist/analog/public` (`pnpm deploy:cf`).

## Phase 1 — Token & contrast audit

- [ ] Write a small script (e.g. `scripts/contrast-audit.mjs`) that parses the preset CSS
      files, resolves the semantic color pairs (background/foreground, primary/
      primary-foreground, destructive/destructive-foreground, muted, card, etc.), and
      computes WCAG contrast ratios for **all 50 preset combinations**.
- [ ] Fix any pair below WCAG AA (4.5:1 normal text, 3:1 large/UI). Record before/after
      in this file.
- [ ] Audit `focus-visible` ring visibility on every preset (3:1 against adjacent colors).
- [ ] Verify every component respects `.dark` + `data-color`/`data-style` — one e2e that
      cycles a representative page through presets and asserts key computed styles change.

## Phase 2 — Theme documentation & custom presets

- [ ] Write "Create a custom color preset" and "Create a custom style preset" guides
      (docs pages under getting-started): full token list with descriptions, a copy-paste
      template CSS file, and registration steps.
- [ ] Document the runtime API (`provideVoltTheme`, `applyVoltTheme`) including SSR
      behavior (no flash of wrong theme — verify and document how; fix if broken).
- [ ] Document dark-mode strategy (class-based) and how to sync with
      `prefers-color-scheme`.

## Phase 3 — Docs completeness sweep

- [ ] Build a checklist (script or manual) comparing `public-api.ts` exports against:
      demo page exists, source snippet exists, usage snippet exists. Every gap is a task.
- [ ] Every component page gets an **API section**: inputs (name, type, default),
      outputs, and exported CVA variant names. Prefer generating from source if cheap;
      hand-written tables are acceptable for v1.
- [ ] Write the two missing guides from SDD §12.4: **customization guide** (how to edit
      copied components, extend variants with CVA, use `cn()`) and a **0.x migration
      notes** page seeded from CHANGELOG breaking changes (v0.7 value-API unification etc.).
- [ ] README.md sync: component list, status table link, install/init instructions match
      reality.

## Phase 4 — Release

- [ ] `COMPONENT_STATUS.md`: update Docs column; promote any component whose only gap
      was docs.
- [ ] `pnpm manifest` if component files changed.
- [ ] `CHANGELOG.md` `## [0.8.0]`; bump root, `projects/volt/package.json`,
      `cli/package.json` to 0.8.0.
- [ ] Release gate: `pnpm release:check` green; deploy docs (`pnpm deploy:cf`) and spot-
