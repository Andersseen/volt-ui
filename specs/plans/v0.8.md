## Context primer (replaces repo analysis — trust this, verify cheaply)

- Theme architecture (SDD.md §6): source tokens `--volt-*` in
  `projects/volt/src/themes/core.css` + preset files; mapped to Tailwind v4 via
  `@theme inline`; semantic vars `--background`, `--foreground`, `--primary`,
  `--destructive`, `--success`, `--warning`, `--error`, `--info`, etc.
  Components use Tailwind utilities (`bg-primary`), never raw `var()`.
- Presets: colors `volt | ember | sage | dusk | glacier` × styles
  `sharp | soft | brutal | ghost | retro` × light/dark = 50 combinations.
  Applied via `data-color` / `data-style` attributes + `.dark` class on the document
  element; runtime API `provideVoltTheme()` / `applyVoltTheme()` in the theme component
  (`projects/volt/src/lib/components/theme/`).
- Consumers import `@voltui/components/themes.css` (exported from
  `projects/volt/package.json`).
- Docs app: AnalogJS, pages in `src/app/pages/`; component demos at
  `(components-docs)/docs/components/<name>.page.ts`; getting-started content at
  `(getting-started)/docs/`; snippets in `src/app/lib/snippets/{index,usage}.ts`.
- Deploy: Cloudflare Pages, output `dist/analog/public` (`pnpm deploy:cf`).

## Phase 1 — Token & contrast audit

- [x] Write a small script (`scripts/contrast-audit.mjs`) that parses the preset CSS
      files and computes WCAG contrast ratios. **Not 50 combinations**: style presets
      (sharp/soft/brutal/ghost/retro) never set a color token (verified — grepped
      `styles/*.css` for exact `--token:` matches against every semantic color name,
      zero hits), so the real surface is 5 colors × light/dark × 13 pairs = 130 checks.
- [x] Fixed 67 failing pairs (every preset had at least one). Each fix is a
      hue/chroma-preserving lightness adjustment computed to clear 4.5:1 (text) or 3:1
      (`--input` border, SC 1.4.11) — brand identity intact. All 130 now pass. Also
      fixed the actual reason this was invisible in the deployed site: `src/styles.css`
      was a ~370-line hand-duplicated fork of the theme tokens, disconnected from
      `projects/volt/src/themes/`; replaced with `@import` of the same source files.
- [x] Focus-visible ring: covered by the same script (`--ring` vs `--background`,
      3:1) — 0 failures found, already compliant everywhere.
- [x] Added `e2e/theme-presets.spec.ts`: cycles the real header color/style pickers and
      dark-mode toggle on a live page, asserts computed `--primary`/`--radius`/
      `--background` change.

## Phase 2 — Theme documentation & custom presets

- [x] Added "Create a Custom Color Preset" and "Create a Custom Style Preset" sections
      to `/docs/themes`: full token list, copy-paste template, registration steps.
- [x] Documented `provideVoltTheme`/`applyVoltTheme` on `/docs/themes`, including SSR
      behavior. It was broken: `provideVoltTheme`'s environment initializer read the
      global `document` (undefined during SSR), so it silently no-op'd on the server —
      fixed by reading Angular's `DOCUMENT` injection token instead. Separately fixed
      the docs app's own FOUC (saved theme only applied post-hydration) with a
      synchronous inline script in `index.html`'s `<head>`.
- [x] Documented dark-mode strategy: class-based, does **not** auto-sync
      `prefers-color-scheme` by design; included the opt-in recipe for consumers who
      want that.

## Phase 3 — Docs completeness sweep

- [x] `scripts/docs-completeness-check.mjs` (`pnpm check:docs-completeness`): compares
      `public-api.ts` exports against snippets/index.ts, snippets/usage.ts, and demo

      tooltip, ...) API shapes this codebase uses.
- [x] Added `/docs/customization` and `/docs/migration-notes`. Migration notes only

## Open questions

- **Deploy** (`pnpm deploy:cf`) was intentionally not run. Deploying to production
  Cloudflare Pages is a hard-to-reverse action affecting a shared/live system, and
  this work is still on an unmerged feature branch (`feat/v0.8-theme-audit-docs`) —
  needs explicit user go-ahead, and normally happens from `main` after merge per the
  CI workflow's own deploy gate (`.github/workflows/ci.yml` only deploys on push to
  `main`). Once merged, CI deploys automatically; a manual `pnpm deploy:cf` from this
  branch was never the right path anyway.
