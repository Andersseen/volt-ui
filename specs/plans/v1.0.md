# Plan v1.0.0 — Stable Release

**Status:** not started
**Entry state:** v0.9.0 published as RC; API frozen; `MIGRATION.md` drafted
**Goal:** ship `@voltui/components@1.0.0` + `@voltui/cli@1.0.0`. No new features — this
minor removes deprecations, runs final verification, and formalizes post-v1 policy.

---

## Context primer (replaces repo analysis — trust this, verify cheaply)

- Everything is expected DONE at entry: forms contract (v0.5), overlay contract (v0.6),
  final component list (v0.7), theme audit + docs (v0.8), consumer validation + API
  freeze (v0.9). If any entry check below fails, STOP and finish the corresponding plan
  first — do not absorb its work here.
- Key files: `public-api.ts` (frozen surface, inventory in `specs/api-freeze-0.9.md`),
  `COMPONENT_STATUS.md`, `MIGRATION.md`, `CHANGELOG.md`, publish scripts `publish:lib` /
  `publish:cli` in root `package.json`.

**Verify entry state:**

```bash
node -p "require('./package.json').version"    # expect 0.9.0
test -f MIGRATION.md && echo ok                 # expect ok
grep -c experimental COMPONENT_STATUS.md        # expect 0 (or only post-v1 section)
pnpm release:check                              # expect green
```

## Phase 1 — Remove deprecations & final API check

- [ ] Remove all deprecation shims added in v0.9 Phase 3 (search for the deprecation
      warning marker used there).
- [ ] Diff current public API against `specs/api-freeze-0.9.md` — the only allowed
      differences are removed deprecated aliases. Any other drift is a bug.
- [ ] Finalize `MIGRATION.md` (0.x → 1.0.0), including the removed aliases.

## Phase 2 — Full regression & final audits

- [ ] `pnpm test:all` green (lint, typecheck, unit, lib build, e2e).
- [ ] Consumer fixture (from v0.9) green against the final build.
- [ ] Accessibility smoke pass: keyboard-only walk through the docs demo of every
      overlay and form component (scripted via existing Playwright helpers where
      possible; manual spot-check otherwise). Record results here.
- [ ] Bundle budgets from v0.9 Phase 2: re-measure, assert no regression.
- [ ] Verify README, docs landing page, and `COMPONENT_STATUS.md` describe 1.0 accurately
      (no "pre-v1", "alpha", or "may change before v1" language remains anywhere —
      grep for it).

## Phase 3 — Policy & docs versioning

- [ ] Update `SDD.md`: version 1.0.0, move §12 roadmap into a changelog reference,
      state the post-v1 stability policy (SDD §12.0 last bullet: breaking changes only
      in majors; features in minors; fixes in patches).
- [ ] Update `specs/SPEC.md`: mark the ladder complete; add a short "post-1.0" section
      pointing to the reserved `@volt-ui/core` headless plan (do NOT plan it here).
- [ ] Add a docs "Versioning & stability" page (semver promise, status label meanings
      post-v1, support policy for Angular majors).

## Phase 4 — Publish

- [ ] `CHANGELOG.md` `## [1.0.0]` — highlights + link to MIGRATION.md.
- [ ] Bump root, `projects/volt/package.json`, `cli/package.json` to 1.0.0.
- [ ] Tag `v1.0.0`; publish `publish:lib` + `publish:cli`; deploy docs
      (`pnpm deploy:cf:main`).
- [ ] Post-publish smoke: `npm i @voltui/components@1.0.0` + `npx @voltui/cli add button`
      in a scratch app; verify install + render.
- [ ] GitHub release with notes; update repo description/badges.

## Out of scope

- Any new component or feature. The `@volt-ui/core` headless primitives layer
  (post-v1 project with its own future spec).
