## Decisions

1. Same architecture as v1.4: sources in `packages/volt/src/lib/quartz/<name>/`, exported from `quartz-api.ts`, no third backend, no adapter framework.
2. **Volt owns `value`.** It is pushed into the directive silently (effect) and only `valueChangeCommitted` flows back to the model and `onChange`.
3. **ToggleGroup value boundary.** Volt: `string[]` in both modes. Quartz: `T | null` (single) / `T[]` (multiple). `toQuartz`/`fromQuartz` in `VoltToggleGroup` are
   the only place the shapes meet. Single mode shows at most the first written value; multiple de-duplicates.
4. **Styling hooks are written by the wrapper** (`data-checked`, `data-selected`, `data-disabled` on host, button and indicator). `toggleGroupItemVariants` is shared
   with the default implementation; no `data-qz-*` selector exists in Volt CSS.
5. Two tiny lib-root helpers, copied by the CLI like `utils.ts`: `quartz-ids.ts` (`VoltQuartzIds`, `providedIn: 'root'`, so it is per application / per SSR request)
   and `quartz-attributes.ts` (`injectAttributeWriter`). Neither imports ng-primitives or Quartz.
6. Radio group id: ng-primitives gives every group an id; the Quartz wrapper generates one with `VoltQuartzIds`. Radio items have an id only when the consumer supplies it;
   toggle items never have one (exactly as with ng-primitives).
7. Tests: one contract per family run against both engines (`testing/group-contract.ts` → `ngp-and-quartz-groups.spec.ts`, 37 tests × 2), a DOM differential
   (`backend-parity-groups.spec.ts`, 11 template cases + API surface), Quartz-only exceptions (`groups-quartz.spec.ts`), and the real-browser consumer suite.

## Known differences (intentional, documented, tested)

- **RTL**: in a real browser Quartz mirrors Left/Right in an RTL horizontal group; ng-primitives 0.131 does not (ArrowLeft is always "previous"). Pinned per engine in
  `e2e/quartz-consumer/browser.spec.ts`. Because of this, RadioGroup/ToggleGroup are **not** claimed "fully equivalent" for RTL keyboard navigation.
- Disabled items: native `disabled` (Quartz) vs `aria-disabled` + focusable (ng-primitives).
- ToggleGroup single with several written values: Quartz shows the first, ng-primitives marks all.
- Removing then re-adding the checked radio: Quartz keeps and re-checks the value, ng-primitives does not.
