## Dependency change (GUARDRAILS rule 10)

`@doqs/analog` `^0.13.0` → `^0.15.0`. Not a new dependency: an upgrade of one already used by Recipes. Read from the published tarball, not from Doqs `main`:

- 0.14.0 hydrates prerendered documentation in place (the resolver prepares the document before the view is created); 0.13 re-rendered it.
- 0.15.0 adds `expandedPreview: 'overlay-compatible'` for playgrounds whose overlays mount on `<body>` (Volt Select).
- Both releases are additive: no exported type, configuration key, frontmatter key, route or `--host-docs-*` token changed. Peer ranges are unchanged (`@analogjs/content ^2.9.2`, Angular `^21.2.2 || ^22.0.0`), which the workspace satisfies.
- Docs-only: `@voltui/components`, `@voltui/cli` and `@voltui/agent` do not depend on it, so no package version changes.

## Forms audit — confirmed defects (each reproduced by a failing test first)

| Family          | Defect                                                                                                   | Fix                                                               | Backends                     |
| --------------- | -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- | ---------------------------- |
| Select          | Pointer press on an option blurred the trigger: control touched + invalid before the value was committed | Focus moving into the select's own popup is not leaving the field | ngp (Quartz already correct) |
| Select          | `required` not exposed to AT                                                                             | Additive `required` input → `aria-required` (+ Angular validator) | both                         |
| Select          | Disabled options had only `data-disabled`; `aria-disabled:` styles never applied                         | `aria-disabled="true"` on the option                              | ngp (Quartz already correct) |
| Native Select   | Consumer `id` replaced by a generated one; `<label for>` named nothing                                   | Expose the primitive's `id` input                                 | ngp                          |
| Checkbox        | Forms setup write (and same-value writes) cleared a bound `indeterminate`                                | Only a value-changing write resolves the mixed state              | both                         |
| Checkbox, Input | Module-level id counters: SSR ids differ per request and from the client                                 | Per-application `VoltIdSource` (`volt-ids.ts`, copied by the CLI) | both                         |
| Form Field      | Removed `<volt-error>` left its id in `aria-describedby` (ng-primitives unregisters only while failing)  | `VoltError` unregisters its id on destroy                         | —                            |

Verified and already correct (tests added where coverage was missing): label association with and without
ids, hint description, `aria-invalid` only when invalid **and** touched, reset, disable/enable from Forms,
ngModel, programmatic writes not echoed, Space activation, indeterminate → checked on activation with one
Forms change, Select keyboard (arrows skip disabled, Home/End, Enter/Space, Escape returns focus), overlay
cleanup on close. Intentional limitations documented on the pages: Select has no typeahead; the trigger
shows `displayWith(value)` because closed options are not rendered.

Error-announcement policy: `<volt-error>` keeps `role="alert"` (backward compatible); it is announced when
inserted, so it is rendered on touched + invalid, not per keystroke. Documented on the Form Field page.
