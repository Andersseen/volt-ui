# Plan v0.7.0 — Composite Components

**Status:** not started
**Entry state:** v0.6.0 released (overlays hardened), `main` green
**Goal:** the remaining `experimental` composite components either meet the forms
contract (v0.5) + overlay contract (v0.6) and get promoted, or are explicitly cut from
the v1 surface. After this minor, the component list for v1 is final.

---

## Context primer (replaces repo analysis — trust this, verify cheaply)

- Library: `projects/volt/src/lib/components/<name>/` (`index.ts`, `<name>.ts`,
  `variants.ts`, `<name>.spec.ts`); conventions in `SDD.md` §5 + `AGENTS.md`
  (standalone, OnPush, signals, CVA in `variants.ts`, ng-primitives behavior layer).
- **Contracts established by earlier minors — reuse, don't reinvent:**
  - Forms contract (v0.5 plan, `specs/plans/v0.5.md`): CVA write/change/touched/disabled
    - ngModel smoke test + invalid-state hook.
  - Overlay contract (v0.6 plan, `specs/plans/v0.6.md`): focus/keyboard/dismissal rules +
    shared Playwright helpers in `e2e/utils/` + SSR safety (guard `document`/`window`).
- Tests: Vitest + `@testing-library/angular`; e2e: Playwright (docs + consumer configs).
- Docs: demo pages `src/app/pages/(components-docs)/docs/components/<name>.page.ts`,
  snippets `src/app/lib/snippets/{index,usage}.ts`, `pnpm manifest` after file changes.
- Status labels: `COMPONENT_STATUS.md`.

**Components in scope:**
`combobox`, `listbox`, `date-picker`, `input-otp`, `file-upload`, `navigation-menu`,
`table`, `resizable`, `autofill`, `sidebar` (layout).

**Verify entry state:**

```bash
node -p "require('./package.json').version"   # expect 0.6.0
grep -c experimental COMPONENT_STATUS.md       # overlays should no longer be experimental
```

## Phase 0 — Keep/cut decision (do this first, it bounds everything)

For each in-scope component, decide **keep for v1** or **cut to post-v1**, based on:
distance from the contracts, ng-primitives support maturity, and docs demand. Record the
decision table here (edit this file). Guidance:

- [ ] `combobox`, `listbox`, `input-otp`, `date-picker` — keep (core shadcn parity),
      unless ng-primitives support is too immature; then cut `date-picker` first.
- [ ] `file-upload`, `navigation-menu`, `resizable`, `autofill` — evaluate honestly;
      cutting is acceptable and cheaper than hardening.
- [ ] `table`, `sidebar` — mostly static; likely cheap to keep.
- [ ] For every **cut** component: remove from `public-api.ts` + manifest + docs nav (keep
      source in-repo on a branch or mark clearly "post-v1, not published"), note in
      CHANGELOG under Removed.

## Phase 1 — Value-selection composites (combobox, listbox, input-otp)

- [ ] Unify their value APIs onto `ControlValueAccessor` (they currently use local value
      APIs). `select` (done in v0.5) is the reference pattern.
- [ ] Combobox: full forms contract + overlay contract for its dropdown (keyboard nav,
      Escape, outside click, focus return), filtering behavior tested.
- [ ] Listbox: forms contract + roving focus/active-option keyboard coverage.
- [ ] Input-OTP: forms contract + focus movement between cells (type, paste, backspace).

## Phase 2 — date-picker & file-upload (if kept)

- [ ] Date-picker: CVA over `Date | null`, calendar keyboard navigation (arrows, PgUp/
      PgDn, Enter), overlay contract for the popup, locale-safe rendering (no
      hardcoded month/day strings; use `Intl`).
- [ ] File-upload: keyboard-accessible trigger, drag/drop with visual state, file list
      rendering, `disabled` state; forms integration if API allows, else documented
      output-based API.

## Phase 3 — Structural composites (navigation-menu, table, resizable, sidebar, autofill — if kept)

- [ ] Navigation-menu: nested menu focus + keyboard per overlay contract; SSR-safe.
- [ ] Table: semantic markup audit (caption/scope/headers), sortable-header keyboard
      access if sorting exists; unit tests.
- [ ] Resizable: keyboard resize (arrow keys on separator with `role="separator"` +
      `aria-valuenow`), pointer behavior e2e.
- [ ] Sidebar layout: keyboard nav, collapse/expand state, tooltip integration (already
      manifest-tested), unit tests.
- [ ] Autofill: define and document its purpose crisply or cut it.

## Phase 4 — Promote, document, release

- [ ] `COMPONENT_STATUS.md`: every kept component is now `beta` or `stable`;
      **no `experimental` rows should remain** (cut components are removed from the table
      or moved to a "post-v1" section).
- [ ] Demo pages + usage snippets updated for every API that changed (esp. the
      local-value → CVA migrations: document the breaking change).
- [ ] `pnpm manifest`.
- [ ] `CHANGELOG.md` `## [0.7.0]` — breaking changes (value API unification, cuts) listed
      explicitly; bump root, `projects/volt/package.json`, `cli/package.json` to 0.7.0.
- [ ] Release gate: `pnpm release:check` then `pnpm test:e2e:ci` green.

## Out of scope

- Theme/token work (v0.8). Docs-completeness sweep beyond touched components (v0.8).
  CLI behavior changes (v0.9) — but DO regenerate the manifest.
