# Plan v0.9.0 — CLI, Distribution & API Freeze (Release Candidate)

**Status:** in progress — Phases 1–3 done
**Entry state:** v0.8.0 released (themes audited, docs complete); three patch releases
since (0.8.1 select-position fix, 0.8.3 v1-readiness bug sweep, 0.8.4 CLI consumer
validation + native-select/range-slider/a11y fixes — see CHANGELOG). Repo is at 0.8.4
as of 2026-08-05.
**Goal:** the consumer experience is validated end-to-end, bundles are audited, and the
public API is **frozen**. 0.9.0 is the release candidate: v1.0 should require no code
changes beyond removing deprecations. Covers SDD.md §12.3 (remaining), §12.6, §12.7.

## Context primer (replaces repo analysis — trust this, verify cheaply)

- CLI `@voltui/cli` in `cli/` (`bin/volt`, `lib/core.js`); commands: `init`, `add`
  (`--install`, `--dry-run`, `--force`, multi-component), `list` (`--status`, `--json`),
  `clear-cache`. Copies from `projects/volt/src/lib`, transforms `volt-*`→`ui-*`,
  `Volt*`→`Ui*`, rewrites `'volt'` imports to `./index`, updates the barrel.
  Manifest: `public/manifest.json` generated by `cli/generate-manifest.js`
  (components, files, deps, stability). CLI tests: `cli/tests/core.spec.js`.
- Library package `@voltui/components` built by ng-packagr (`pnpm build:lib` →
  `dist/volt`); exports `themes.css` + `themes/*`. Publish scripts: `publish:lib`,
  `publish:cli`. Consumer e2e: `playwright.consumer.config.ts` (+ `pnpm test:e2e:consumer`).
- Runtime deps the CLI installs for consumers: `ng-primitives`,
  `class-variance-authority`, `clsx`, `tailwind-merge`.
- Conventions: `SDD.md`, `AGENTS.md`. Status: `COMPONENT_STATUS.md`.
- **A consumer fixture already exists** (`e2e/consumer/` + `playwright.consumer.config.ts`
  - `pnpm test:e2e:consumer`) — but it imports `Volt*` symbols straight from the built
    npm package (`e2e/consumer/src/main.ts`) for a hand-picked subset of
    overlay/primitive components (dialog, drawer, dropdown-menu, popover, select, toast,
    meter, progress, radio, avatar, checkbox…). It validates the **npm-import path**
    (Phase 1's 4th bullet is largely satisfied by this already). It does **not** exercise
    `volt init` / `volt add`, so it does not cover Phase 1's 1st–3rd bullets (the
    CLI copy-paste path, for every component, including the no-Tailwind error path).
    Don't rebuild this fixture — add a sibling one (or a separate script) that drives the
    CLI instead, and keep both in CI.
- `scripts/contrast-audit.mjs` (`pnpm check:contrast`) was added for the v0.8 WCAG audit
  — unrelated to Phase 2's bundle/perf work, just don't recreate it.
- No `CHANGELOG.md` `[Unreleased]` section exists yet for 0.9 work; Phase 4 starts it.

## Phase 1 — Consumer validation end-to-end ✅ done (2026-08-05)

- [x] Created a **new** fixture `e2e/consumer-cli/` (didn't touch `e2e/consumer/`, that
      one stays as the npm-import regression test): `e2e/consumer-cli/generate.mjs` runs
      `volt init` + `volt add <every component>` (all 41, read from `volt list --json`)
      into `e2e/consumer-cli/src/ui/` (gitignored, regenerated each run), then
      `e2e/consumer-cli/main.ts` imports the whole barrel + bootstraps a real Angular app
      built via the same `@analogjs/vite-plugin-angular` + `@tailwindcss/vite` stack as
      the npm fixture. Wired into CI as `pnpm test:e2e:consumer-cli` (own
      `playwright.consumer-cli.config.ts`, `pretest:e2e:consumer-cli` hook regenerates
      the fixture first), added to `test:all` and both `.github/workflows/{ci,release}.yml`
      alongside the existing consumer step. Root `playwright.config.ts`'s `testIgnore`
      widened to `/consumer(-cli)?\.spec\.ts/` so the docs-app e2e run doesn't also pick
      up the new spec.
- [x] Fixed everything this surfaced — two real CLI bugs, both were silently shipping
      broken consumer code before this phase: 1. **Shared lib-root files never copied.** `projects/volt/src/lib/utils.ts` and
      `form-control-state.ts` are imported by components via `'../../utils'` /
      `'../../form-control-state'`. The manifest's dependency detector
      (`cli/generate-manifest.js`) only resolves `components/`/`layouts/`-folder
      imports, so these two lib-root files were never tracked, never copied, and
      their import path was never rewritten — `volt add button` (also badge,
      dialog) and `volt add checkbox` (also input, input-otp, listbox, radio, select,
      slider, switch, textarea, toggle, toggle-group — 11 components) shipped a file
      importing a path that doesn't exist in the consumer's project. **14 of 41
      components (34%) were affected.** Fixed in `cli/lib/core.js`:
      `detectSharedFileDependencies()` + `copySharedFileIfNeeded()` (idempotent —
      re-adding a second component that also needs `utils.ts` doesn't error) copy
      `SHARED_LIB_FILES` flat into `targetDir`, and `transformContent()` rewrites the
      import to `'../utils'` / `'../form-control-state'`. Covered by new tests in
      `cli/tests/core.spec.js`. 2. **Cross-component relative import path never rewritten.** `layouts/sidebar/sidebar.ts`
      imports its `tooltip` dependency as `'../../components/tooltip'` instead of via
      the `'volt'` barrel. The manifest correctly tracked `tooltip` as a dependency
      and copied its files, but the import **path** in the copied `sidebar.ts` was
      left untouched, pointing outside the consumer's project. Fixed with a generic
      rule in `transformContent()`: any `(\.\./)+  (components|layouts)/<name>` import
      collapses to `'../<name>'`, matching the CLI's flat sibling layout. Covered by
      a new test.
      Verified across the full 41-component set: `e2e/consumer-cli` builds clean (530
      modules, zero errors) and boots with zero runtime console errors.
- [x] `volt init` had **no** Tailwind-detection logic at all before this phase — it just
      writes an empty `index.ts` barrel. Added `detectTailwindSetup()` (checks
      `tailwindcss` in `package.json` deps + a `@import 'tailwindcss'` in the common
      stylesheet locations) + `formatTailwindGuidance()` in `cli/lib/core.js`, wired into
      `cli/bin/volt`'s `init` command: prints non-blocking setup guidance (install
      command + stylesheet snippet + docs link) when Tailwind isn't detected, silent
      otherwise. Chose guidance over a hard error — `volt init` just scaffolds the `ui/`
      barrel, and consumers may reasonably configure Tailwind right after. Covered by
      unit tests (`core.spec.js`) and a CLI-binary integration test.
- [x] npm-package path was already covered by `e2e/consumer/` + `pnpm test:e2e:consumer`
      (built `dist/volt` import, theme CSS, overlay/primitive rendering); reran it as
      part of this phase's release gate — still green, no changes needed.

  **Full verification run for this phase:** `pnpm lint`, `pnpm typecheck`,
  `pnpm test:run` (252 tests at the time, 42 in `cli/tests/core.spec.js`; 264 after the
  Open Questions work below), `pnpm check:ai-docs`, `pnpm pack:cli`,
  `pnpm test:e2e:consumer`, `pnpm test:e2e:consumer-cli` — all green.

## Phase 2 — Bundle & performance audit ✅ done (2026-08-05)

- [x] **Tree-shaking: confirmed working correctly**, despite the library shipping as a
      single flat FESM file (`dist/volt/fesm2022/voltui-components.mjs`, 412 KB raw / 142
      classes — ng-packagr's normal output shape, not a red flag by itself). Built a
      throwaway consumer fixture (Vite + `@analogjs/vite-plugin-angular`, same stack as
      `e2e/consumer/`) importing **only** `VoltButton`, `vite build`'d it, then grepped
      the minified output for identifiers unique to unrelated components (`volt-dialog`,
      `NgpDialog`, `voltDropdownMenu`, `input-otp`, `range-slider`, `voltNativeSelect`,
      `ngpTabs`, `floating-ui`/`computePosition`/`autoUpdate`/`ngpOverlay` for
      overlay/positioning code) — **zero occurrences of any of them**, while
      `volt-button`/`NgpButton` were present as expected. Rollup's/esbuild's dead-code
      elimination on the flat FESM works because `projects/volt/package.json` declares
      `"sideEffects": ["./themes.css", "./themes/**/*.css"]` (everything else is
      correctly marked pure/tree-shakeable).
- [x] **Theme CSS size: the 25-presets-to-everyone concern is already resolved, not a
      v0.9 problem.** `dist/volt/themes.css` is **249 bytes** — it only
      `@import`s `core.css` (5.9 KB, the shared Tailwind `@theme inline` mapping + base
      tokens) plus **one default preset** (`volt-sharp`, itself just two ~50-byte
      `@import`s of `colors/volt.css` + `styles/sharp.css`). The file's own header comment
      says exactly why: "intentionally imports a single preset to avoid bundling every
      theme." All 36 per-dimension entry points already exist and are built + exported
      (`themes/colors/<name>.css` ×5, `themes/styles/<name>.css` ×5,
      `themes/presets/<color>-<style>.css` ×25, `dist/volt/themes` total: **16.3 KB** for
      literally everything). Consumers who want a specific combo import
      `@voltui/components/themes/presets/<color>-<style>.css` instead of `themes.css`;
      this is already documented in the source file itself. Nothing to build here —
      confirmed it works and left it as-is.
- [x] **Docs app Lighthouse/perf pass** (`chrome-devtools` MCP, production build served
      via `wrangler pages dev dist/analog/public`) on 3 pages: home (`/`), the full
      component grid (`/docs/components`, ~39 cards), and a demo page with a live widget
      (`/docs/components/select`). All three: **LCP 113–143 ms, CLS 0.00, TTFB 29–46
      ms**, `RenderBlocking` insight reports 0 ms estimated savings on all three (nothing
      to fix — per the audit's own guidance, a page already an order of magnitude under
      the "good" LCP threshold of 2.5s gets a clean bill, not invented work). Prerendering
      (Analog SSG) is doing its job. No egregious issues found, nothing fixed.
- [x] **Budget baselines** (record here, assert-no-regression reference for v1.0): - Full library FESM (all 42 components): **412 KB raw**. - Consumer bundle, Angular 21 zoneless baseline (bootstrap + JIT compiler, **zero**
      Volt components): **256 KB raw / 70 KB gzip**. - Consumer bundle, **+1 Volt component** (`button`): **445 KB raw / 133 KB gzip**
      (+189 KB raw / +63 KB gzip over baseline — this delta is dominated by
      `ng-primitives`' shared runtime, which any first primitive pays once
      — `ng-primitives-interactions`/`state`/`internal` — plus `tailwind-merge`, not
      by `VoltButton` itself, which is ~3 KB source). - Consumer bundle, **+5 Volt components / 12 classes** (button, badge, checkbox,
      dialog, select, tabs): **668 KB raw / 194 KB gzip** (+222 KB raw / +61 KB gzip
      over the button-only build) — confirms marginal cost scales with what's actually
      imported (~15 KB gzip/component average for the 2nd–5th component) rather than
      the "first component" shared-runtime tax repeating. - `themes.css` (default, single preset): **249 bytes**. Full `themes/` directory
      (all 36 files, everything available): **16.3 KB**. - Docs app LCP: **113–143 ms** on all 3 audited pages (home, component grid, a
      component demo). CLS: **0.00** on all 3. - v1.0 regression check: re-run the same throwaway-fixture method (button-only +
      the 5-component build) and the same 3-page Lighthouse pass; flag if raw/gzip
      sizes grow >15% or LCP exceeds 500 ms without a corresponding feature reason.

## Phase 3 — API freeze ✅ done (2026-08-06)

- [x] **Public API inventory generated**: `specs/api-freeze-0.9.md` (41 component
      directories, 87 exported directives/components, 301 inputs, 42 outputs). Written by
      a new `scripts/generate-api-freeze.mjs`, which shares its extraction logic with
      `scripts/generate-api-reference.mjs` via a new `scripts/lib/api-extract.mjs` module
      (refactored out so the docs-app TS data and the freeze markdown can never drift
      from each other). Re-run `node scripts/generate-api-freeze.mjs` after any future
      input/output/selector/CVA change and re-check the diff into git — this is the
      reference v1.0 Phase 1 diffs the final API against.
- [x] **Consistency review — found and fixed 4 real issues**, not just naming: 1. **Extraction bug corrupting the live docs site**: `extractVariants()`'s regex
      for CVA variant _options_ matched any `word:` pattern in the class-string
      value, including Tailwind pseudo-class prefixes (`hover:`, `focus-visible:`,
      `data-[selected]:`) embedded _inside_ an option's class string — not real
      option keys. This silently corrupted the "API Reference" panel shown on the
      docs site for `toggle` (showed 8 fake options instead of 4 real ones),
      `pagination`, `toggle-group`, and `textarea`. Fixed the regex to require the
      match be immediately followed by a quote (`key: '...'`), verified against
      every affected component's actual `variants.ts`. 2. **Selector naming inconsistency**: `VoltNavigationMenuLink` used
      `a[volt-navigation-menu-link]` (kebab-case) — the only attribute selector in
      the whole library not using camelCase (`voltComboboxInput`, `voltNativeSelect`,
      etc.); the source even carried an unexplained `eslint-disable` for it. Renamed
      to `a[voltNavigationMenuLink]`, kept the old attribute working via multi-selector
      syntax with a dev-mode `console.warn` deprecation notice (`ElementRef` +
      `isDevMode()`, since there's no built-in mechanism to warn on legacy _input_
      usage the way there is for detecting a legacy _attribute_). This surfaced two
      more bugs while fixing it: the existing unit test used `voltNavigationMenuLink`
      (camelCase) against a selector that was kebab-only, so the directive silently
      never attached and the test never actually exercised it (fixed: test now
      asserts `data-active`, proving attachment); and the `usage.ts` snippet showed
      `<volt-navigation-menu-link>...</volt-navigation-menu-link>` as if it were an
      element with open/close tags, when the selector has always been
      attribute-only — that snippet would never have worked for a consumer copying it. 3. **Output naming**: `VoltResizableHandle.resizing` and
      `VoltFileUpload`/`VoltFileDropzone.dragOver` are continuous boolean _state_
      outputs (same category as `checkedChange`/`pressedChange`) but lacked the
      `Change` suffix used everywhere else for that category. Renamed to
      `resizingChange`/`dragOverChange`, kept the old names emitting in parallel
      (no shim warning for these — Angular has no reliable way to detect whether a
      consumer is listening to a specific `@Output`, unlike the ElementRef-attribute
      trick used for the selector case above).
      **Found while fixing, not obvious in advance**: `hostDirectives.outputs` cannot
      map one primitive output to two public aliases — listing
      `['ngpXDragOver: dragOverChange', 'ngpXDragOver: dragOver']` silently wires up
      _neither_ (confirmed empirically: a `data-dragover` attribute update proved the
      primitive's own state changed, but nothing reached either Angular output).
      Fixed by `inject()`-ing the hostDirective instance directly and bridging its
      real output via `outputToObservable(...).pipe(takeUntilDestroyed()).subscribe(...)`
      to both public outputs manually — this also revealed that a class's own
      same-named `output()` field is entirely shadowed/dead when `hostDirectives`
      already claims that public name (unlike `input()`, where a same-named class
      field _does_ fan out correctly alongside a hostDirective mapping, confirmed
      separately). All 4 changes covered by regression tests that fail without the
      fix (verified manually for the selector and output cases by reverting locally). 4. `disabled`/`size`/`variant` input naming, CVA variant group key names,
      and every other selector prefix: reviewed against the full inventory,
      already 100% consistent — nothing else to change.
- [x] `@experimental`: none needed — `COMPONENT_STATUS.md` already lists zero
      experimental components (fixed at v0.7).
- [x] Deprecation shims added for both renames above (selector + 2 outputs), each with
      a regression test proving the deprecated path still works.
