# Plan v0.9.0 — CLI, Distribution & API Freeze (Release Candidate)

**Status:** in progress — Phase 1 done
**Entry state:** v0.8.0 released (themes audited, docs complete); two patch releases
since (0.8.1 select-position fix, 0.8.3 v1-readiness bug sweep — see CHANGELOG). Repo is
at 0.8.3 as of 2026-08-05.
**Goal:** the consumer experience is validated end-to-end, bundles are audited, and the
public API is **frozen**. 0.9.0 is the release candidate: v1.0 should require no code
changes beyond removing deprecations. Covers SDD.md §12.3 (remaining), §12.6, §12.7.

## Context primer (replaces repo analysis — trust this, verify cheaply)

- CLI `@voltui/cli` in `cli/` (`bin/volt`, `lib/core.js`); commands: `init`, `add`
  (`--install`, `--dry-run`, `--force`, multi-component), `list` (`--status`, `--json`),
  `clear-cache`. Copies from `projects/volt/src/lib`, transforms `volt-*`→`ui-*`,
  `Volt*`→`Ui*`, rewrites `'volt'` imports to `./index`, updates the barrel.
  Manifest: `public/manifest.json` generated by `cli/generate-manifest.js`
  (components, files, deps, stability). CLI tests: `cli/tests/core.spec.js`.
- Library package `@voltui/components` built by ng-packagr (`pnpm build:lib` →
  `dist/volt`); exports `themes.css` + `themes/*`. Publish scripts: `publish:lib`,
  `publish:cli`. Consumer e2e: `playwright.consumer.config.ts` (+ `pnpm test:e2e:consumer`).
- Runtime deps the CLI installs for consumers: `ng-primitives`,
  `class-variance-authority`, `clsx`, `tailwind-merge`.
- Conventions: `SDD.md`, `AGENTS.md`. Status: `COMPONENT_STATUS.md`.
- **A consumer fixture already exists** (`e2e/consumer/` + `playwright.consumer.config.ts`
  - `pnpm test:e2e:consumer`) — but it imports `Volt*` symbols straight from the built
    npm package (`e2e/consumer/src/main.ts`) for a hand-picked subset of
    overlay/primitive components (dialog, drawer, dropdown-menu, popover, select, toast,
    meter, progress, radio, avatar, checkbox…). It validates the **npm-import path**
    (Phase 1's 4th bullet is largely satisfied by this already). It does **not** exercise
    `volt init` / `volt add`, so it does not cover Phase 1's 1st–3rd bullets (the
    CLI copy-paste path, for every component, including the no-Tailwind error path).
    Don't rebuild this fixture — add a sibling one (or a separate script) that drives the
    CLI instead, and keep both in CI.
- `scripts/contrast-audit.mjs` (`pnpm check:contrast`) was added for the v0.8 WCAG audit
  — unrelated to Phase 2's bundle/perf work, just don't recreate it.
- No `CHANGELOG.md` `[Unreleased]` section exists yet for 0.9 work; Phase 4 starts it.

## Phase 1 — Consumer validation end-to-end ✅ done (2026-08-05)

- [x] Created a **new** fixture `e2e/consumer-cli/` (didn't touch `e2e/consumer/`, that
      one stays as the npm-import regression test): `e2e/consumer-cli/generate.mjs` runs
      `volt init` + `volt add <every component>` (all 41, read from `volt list --json`)
      into `e2e/consumer-cli/src/ui/` (gitignored, regenerated each run), then
      `e2e/consumer-cli/main.ts` imports the whole barrel + bootstraps a real Angular app
      built via the same `@analogjs/vite-plugin-angular` + `@tailwindcss/vite` stack as
      the npm fixture. Wired into CI as `pnpm test:e2e:consumer-cli` (own
      `playwright.consumer-cli.config.ts`, `pretest:e2e:consumer-cli` hook regenerates
      the fixture first), added to `test:all` and both `.github/workflows/{ci,release}.yml`
      alongside the existing consumer step. Root `playwright.config.ts`'s `testIgnore`
      widened to `/consumer(-cli)?\.spec\.ts/` so the docs-app e2e run doesn't also pick
      up the new spec.
- [x] Fixed everything this surfaced — two real CLI bugs, both were silently shipping
      broken consumer code before this phase: 1. **Shared lib-root files never copied.** `projects/volt/src/lib/utils.ts` and
      `form-control-state.ts` are imported by components via `'../../utils'` /
      `'../../form-control-state'`. The manifest's dependency detector
      (`cli/generate-manifest.js`) only resolves `components/`/`layouts/`-folder
      imports, so these two lib-root files were never tracked, never copied, and
      their import path was never rewritten — `volt add button` (also badge,
      dialog) and `volt add checkbox` (also input, input-otp, listbox, radio, select,
      slider, switch, textarea, toggle, toggle-group — 11 components) shipped a file
      importing a path that doesn't exist in the consumer's project. **14 of 41
      components (34%) were affected.** Fixed in `cli/lib/core.js`:
      `detectSharedFileDependencies()` + `copySharedFileIfNeeded()` (idempotent —
      re-adding a second component that also needs `utils.ts` doesn't error) copy
      `SHARED_LIB_FILES` flat into `targetDir`, and `transformContent()` rewrites the
      import to `'../utils'` / `'../form-control-state'`. Covered by new tests in
      `cli/tests/core.spec.js`. 2. **Cross-component relative import path never rewritten.** `layouts/sidebar/sidebar.ts`
      imports its `tooltip` dependency as `'../../components/tooltip'` instead of via
      the `'volt'` barrel. The manifest correctly tracked `tooltip` as a dependency
      and copied its files, but the import **path** in the copied `sidebar.ts` was
      left untouched, pointing outside the consumer's project. Fixed with a generic
      rule in `transformContent()`: any `(\.\./)+  (components|layouts)/<name>` import
      collapses to `'../<name>'`, matching the CLI's flat sibling layout. Covered by
      a new test.
      Verified across the full 41-component set: `e2e/consumer-cli` builds clean (530
      modules, zero errors) and boots with zero runtime console errors.
- [x] `volt init` had **no** Tailwind-detection logic at all before this phase — it just
      writes an empty `index.ts` barrel. Added `detectTailwindSetup()` (checks
      `tailwindcss` in `package.json` deps + a `@import 'tailwindcss'` in the common
      stylesheet locations) + `formatTailwindGuidance()` in `cli/lib/core.js`, wired into
      `cli/bin/volt`'s `init` command: prints non-blocking setup guidance (install
      command + stylesheet snippet + docs link) when Tailwind isn't detected, silent
      otherwise. Chose guidance over a hard error — `volt init` just scaffolds the `ui/`
      barrel, and consumers may reasonably configure Tailwind right after. Covered by
      unit tests (`core.spec.js`) and a CLI-binary integration test.
- [x] npm-package path was already covered by `e2e/consumer/` + `pnpm test:e2e:consumer`
      (built `dist/volt` import, theme CSS, overlay/primitive rendering); reran it as
      part of this phase's release gate — still green, no changes needed.

  **Full verification run for this phase:** `pnpm lint`, `pnpm typecheck`,
  `pnpm test:run` (252 tests, 42 in `cli/tests/core.spec.js`), `pnpm check:ai-docs`,
  `pnpm pack:cli`, `pnpm test:e2e:consumer`, `pnpm test:e2e:consumer-cli` — all green.

## Phase 2 — Bundle & performance audit

- [ ] Tree-shaking: build the fixture importing only `button`; verify unrelated
      component code is not in the output (source-map or size check). Record numbers here.
- [ ] Theme CSS size: measure `themes.css`; if all 25 presets ship to everyone, evaluate
      per-preset entry points (`themes/*` exports already exist) and document how to
      import only what's used.
- [ ] Docs app: run a Lighthouse/perf pass on 2–3 heavy pages; fix egregious issues only.
- [ ] Set budget baselines and record them in this file (lib bundle per component avg,
      themes.css size, docs LCP) so v1.0 can assert no regression.

## Phase 3 — API freeze

- [ ] Generate the public API inventory: every export in `public-api.ts`, with each
      component's inputs/outputs/selectors/CVA export names (a script dumping this to
      `specs/api-freeze-0.9.md` is ideal — it becomes the freeze reference).
- [ ] Review for consistency BEFORE freezing: naming patterns (`disabled`, `size`,
      `variant` uniform everywhere), selector prefixes, output naming
      (`(valueChange)` style), CVA variant key names. Fix inconsistencies NOW — this is
      the last minor where renames are allowed.
- [ ] Mark anything deliberately unstable with a documented `@experimental` JSDoc tag
      (should be rare or none after v0.7 cuts).
- [ ] Add deprecation shims where renames happened (old name works + console warning),
      to be removed in v1.0.

## Phase 4 — Release candidate

- [ ] `CHANGELOG.md` `## [0.9.0]` with a dedicated **"Upgrade to 1.0"** notes section
      (deprecations and their replacements).
- [ ] Draft `MIGRATION.md` (0.x → 1.0): value-API changes from v0.7, renames from
      Phase 3, removed components.
- [ ] Bump root, `projects/volt/package.json`, `cli/package.json` to 0.9.0.
- [ ] Release gate: `pnpm release:check`, `pnpm test:e2e:ci`, consumer fixture green.
- [ ] Publish 0.9.0 to npm (`publish:lib`, `publish:cli`) as the public RC; announce in
      README that API is frozen for 1.0.

## Out of scope

- New features/components. Docs content beyond migration notes. Post-v1 headless layer
  (`@volt-ui/core`) — explicitly reserved, do not start it.
