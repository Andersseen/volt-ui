# Plan v1.2 — Application DX & Composition

**Status:** implemented, release-ready except the version bump (deliberately a separate PR — see
"Release"). Verification results are recorded under "Exit state".
**Target version:** 1.2.0 (from 1.1.0). Minor: additive only, 1.x API promise holds.
**Base:** `main` @ `93a6035`.
**Source:** a benchmark of how Volt's atoms compose into an ordinary admin workflow, informed by
the ForgeCMS audit. ForgeCMS is evidence, not a dependency: nothing here imports it or copies its
domain.

1.1 improved individual atoms. 1.2 asks whether they survive _application workflows_ — list,
filter, edit, validate, retry, delete — and fixes what that exposes. It does not add a DataTable, a
form framework, a Quartz/headless layer, or a Sidebar rewrite.

## Entry state (verified)

- `pnpm typecheck` clean, `pnpm test:run` green on `93a6035`; library 1.1.0.
- Historical ForgeCMS workarounds (Button ARIA forwarding, `voltButton`, Input/Textarea id,
  FormField label/describedby, programmatic invalid/touched, controlled dialogs, toast service,
  Alert, Spinner) were all solved by 1.1. The benchmark re-proves them; no 1.2 change is made for them.

### Investigated, not reproduced

- **Pricing block interaction failure under Wrangler.** `e2e/ssr-gallery.spec.ts` drives the billing
  switch after hydration against the real worker, on the pre-fix and post-fix builds: it passes on
  both. The earlier failure either predates 1.1's Switch id fix or was a side effect of the
  logged server errors. Not reproducible on `93a6035`; the test stays as a regression guard.
- **Blocks under `prefers-reduced-motion`.** All 11 blocks settle (no infinite animation, no text
  stuck at `opacity: 0`); the same assertion fails with motion enabled, so it discriminates. No
  block change was needed.

## Decisions

1. **One dialog API, not several.** `dismissible` (live) beside the existing open-time options.
   `canClose` callbacks and ref update methods were rejected: a boolean bound to a signal is all the
   pending case needs.
2. **`aria-disabled` is styling only.** Documented everywhere: the consumer guards the handler.
3. **`VoltEmptyState` is the only new atom.** PageHeader, StatCard, SearchToolbar, SettingsCard,
   ErrorState, LoadingState stay compositions (recipes/layouts/blocks). ErrorState = EmptyState +
   Alert; LoadingState = Spinner/Skeleton.
4. **Alert and Spinner stay beta.** The benchmark needed no API change and both ran through the npm
   and CLI paths, but `COMPONENT_STATUS.md` defines beta as "has not had a release of real-world
   use", and 1.1 shipped weeks ago. Promotion candidates for 1.3.
5. **Recipes are not in `@voltui/components`.** `src/app/recipes/*`, shown with `@voltui/components`
   imports, tested in jsdom, compiled by `check:copied-source`. They take the async function as an
   input (`[save]`, `[search]`, `[fetch]`) so a consumer replaces exactly one thing.
6. **Settings: layout = structure, recipe = behaviour.** The layout gained a pointer comment, no state.
7. **Sidebar:** one defect fixed (collapsed names). No resize/persistence/overlay/focus engine.
8. **Version bump is not in this PR.** Merging a bumped `package.json` to `main` publishes to npm
   (`release.yml`), and the brief says not to publish automatically. Release = a one-line bump PR.

## Open questions

- Should `VoltCombobox` expose the typed query (an `(queryChange)` output) and a loading/no-results
  slot? The async-search recipe works around both (native `input` event bubbling; status line
  beside the control), but a server-searched combobox also has `items` re-filtered by label on the
  client. Candidate for 1.3 — needs a second consumer asking before it becomes API.
- `NgpListbox.scrollIntoViewIfNeeded` touches `window` during SSR (upstream, ng-primitives 0.110.2).
  Left as a known limitation; `check-ssr.mjs` lists the two affected routes with the reason.
- Mobile Sidebar claims `aria-modal` without a focus trap. Belongs to the Quartz-backed rewrite.
- `@axe-core/playwright` is not a dependency and rule 10 requires a plan justification before adding
  one. Accessibility is asserted with roles/names, `aria-*` state and real keyboard paths instead.
