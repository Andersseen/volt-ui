# Plan v1.1 — Consumer DX

**Status:** done — pending release (version bump + merge to `main` publishes; see RELEASING.md)
**Target version:** 1.1.0 (from 1.0.1). Minor: additive only, 1.x API promise holds.
**Source:** consumer audit across Volt-using apps (DevFlare, ForgeCMS, Wisp, Palette Crafter,
Lumen Icons, CV Builder, Agentyx, Angular Movement site, Quartz site) plus
`specs/v2/plans/04-component-contracts.md` (F11).

Volt works as an **atom layer** inside apps that own their layout, identity and state.
This minor makes the existing atoms easier and safer to consume. It does not migrate off
ng-primitives, add Quartz, rework Sidebar behavior, or grow the catalog beyond two atoms
(Alert, Spinner).

## Design decisions

1. **Class contract.** Host-styled atoms: `class = input('')`, host `[class]` = `cn(base, variants, class())`.
   Wrappers around one native control (Input, Textarea, Select trigger, Label, Hint, Error,
   SearchClear, Sidebar parts): `class` is merged onto the native element and the consumer's
   **static** class tokens are removed from the host (`forwardClassFromHost()` / `forwardAttributesFromHost()` in the new
   shared `host-forwarding.ts`) so utilities are not applied twice. `display: contents` was rejected:
   overlay triggers (`<volt-button [voltTooltip]>`) measure the host, and FormField's
   `space-y-*` margins do not apply to `contents` boxes.
2. **`<volt-button>` keeps applying `class` to both host and native button** (1.x compat:
   `ml-auto`/placement on the host is widespread). Exact control → `voltButton`.
3. **Native button directive** `button[voltButton], a[voltButton]` (`VoltNativeButton`), same
   `buttonVariants`. Anchors never receive `disabled`/`aria-disabled` emulation — documented.
4. **ARIA on `<volt-button>`:** a fixed set (`aria-label`, `-labelledby`, `-describedby`,
   `-expanded`, `-pressed`, `-controls`, `-haspopup`) as aliased inputs forwarded to the native
   button; static copies are removed from the host. No generic passthrough.
5. **Toast:** `VoltToastService` (show/success/error/warning/info/dismissAll) renders a
   Volt-owned toast view through `NgpToastManager`; `provideVoltToast()` wraps config. Existing
   `NgpToastManager`/`provideToastConfig` re-exports stay (low-level, documented as such).
6. **Dialog:** `VoltDialogService.open()` (imperative) and `ng-template[voltDialogRoot]` with
   `[(open)]` (controlled), both over `NgpDialogManager`. Opening from a signal change is
   deferred to a microtask (never creates views inside `effect()`, never on the server). A render
   hook was tried first and broke initial focus: NgpFocusTrap's own `afterNextRender` does not run
   when registered from inside another render hook (caught by the consumer e2e).
   Works with `voltDrawerContent` too.
7. **Deprecated (kept):** `VoltButton.customClass` → `class`.
8. **ToggleGroup single mode** keeps `string[]`; recorded as a 2.0 candidate.

## Future-major candidates (not in 1.x)

- `VoltToggleGroup` single mode: `value: string | undefined` instead of `string[]`.
- `<volt-button>` applying consumer `class` to host **and** native button — remove the host
  copy in 2.0 (or retire the wrapper in favour of `voltButton`).
- `VoltButton.customClass` removal.
- Checkbox / Switch / Radio / Toggle: route `class` to the native control (today it styles the
  host, which is also the layout box).
