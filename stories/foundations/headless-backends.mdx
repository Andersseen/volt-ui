# Headless backends

Volt UI separates three things that used to travel together:

| Axis             | Choices                                       | Chosen by                                |
| ---------------- | --------------------------------------------- | ---------------------------------------- |
| Headless backend | `ng-primitives` (default), `quartz`           | the import path, or `volt init --base=…` |
| Colour preset    | Volt, Ember, Sage, Dusk, Glacier, or your own | `applyVoltTheme` / the theme CSS         |
| Style preset     | Sharp, Soft, Brutal, Ghost, Retro             | `applyVoltTheme` / the theme CSS         |

Changing the backend never changes the palette or the visual style. The accessibility and behavioural
contract belongs to Volt UI; the primitive library is an implementation detail of the backend.

## Quartz Headless — experimental

Seven component families can be backed by [Quartz Headless](https://github.com/Andersseen/quartz) instead of
ng-primitives: **Accordion** (accordion + item + trigger + content), **Checkbox**, **Radio** (group + item), **Switch**, **Tabs** (tabs + list + trigger + content), **Toggle** and **ToggleGroup** (group + item). Everything else is ng-primitives only.

### Package mode

```bash
npm install @voltui/components @quartz-headless/core @quartz-headless/primitives
```

```ts
// ng-primitives (default)
import { VoltCheckbox, VoltRadioGroup, VoltRadioItem, VoltToggleGroup } from '@voltui/components';

// Quartz Headless — same names, selectors, inputs, models and outputs
import {
  VoltCheckbox,
  VoltRadioGroup,
  VoltRadioItem,
  VoltToggleGroup,
} from '@voltui/components/quartz';
```

Import **one** implementation of a given component per Angular component: two classes sharing the
`volt-checkbox` selector in the same `imports` array is an error. Both entry points can live in the
same application (for example Quartz Checkbox next to an ng-primitives Dialog); the Quartz entry
point never loads ng-primitives and the main entry point never loads Quartz.

### CLI mode

```bash
npx @voltui/cli init --base=quartz
npx @voltui/cli add checkbox radio switch toggle toggle-group tabs accordion --base=quartz
```

The base is recorded in `volt.json` and reused by later `volt add` calls. A flag that contradicts
`volt.json`, or a component without a Quartz implementation, is rejected rather than silently
generating the other engine's source.

### Requirements

- `@quartz-headless/core` and `@quartz-headless/primitives` **0.16.x** (optional peers of `@voltui/components`).
- Angular 21.2+. Quartz 0.16 declares `@angular/*` peers of `^21.0.0`: on **Angular 22** npm needs
  `--legacy-peer-deps` (or an `overrides` entry) until Quartz publishes widened peer ranges. The
  components run correctly on Angular 22 — the compatibility check builds and drives them there.

### Group controls

`ToggleGroup.value` is a `string[]` in single **and** multiple mode under both backends: Quartz's
`T | null` / `T[]` split is mapped inside the wrapper, so switching backend never changes your data model.
`RadioGroup.value` is `string | null`. Ids rendered by Quartz's counter are replaced, so server and browser agree.

### Tabs and Accordion

- **Tabs**: `activateOnFocus` (default on) is Volt's boolean; Quartz's `activationMode` is mapped inside the wrapper. With it off, arrows move
  focus only and a click, Enter or Space selects (ng-primitives: pointer only). An undefined `value` shows the first tab and emits nothing.
- **Accordion**: `type`, `collapsible`, `value` (`string | string[] | null`) and `disabled` behave as with ng-primitives; Quartz's habit of opening
  the first item is suppressed. Every enabled trigger stays a Tab stop. A closed panel is `visibility: hidden`, so it leaves the keyboard and the
  accessibility tree and still animates.
- Ids are counted per application, so the `aria-controls` / `aria-labelledby` references in the server HTML equal the hydrated ones.
- The single non-collapsible open accordion item is `aria-disabled` with Quartz (as the WAI-ARIA pattern asks); ng-primitives omits it.

### What is guaranteed to match

Role, accessible name, `aria-checked` (including `mixed`) / `aria-pressed`, the native `<button>`,
keyboard and pointer activation, the `data-checked` / `data-indeterminate` / `data-selected` /
`data-disabled` styling hooks, computed colours, geometry and focus ring, `ControlValueAccessor`
behaviour (silent writes, dirty/touched, reset, disable), and SSR output plus hydration.

### Known differences

- Disabled **Toggle**: ng-primitives keeps the button focusable with `aria-disabled`; Quartz uses the
  native `disabled` attribute, which removes it from the tab order.
- Disabled Radio / ToggleGroup items follow the same rule. A single-mode ToggleGroup given several values shows only the first with Quartz.
- Engine-owned attributes differ (`data-qz-*` versus `data-hover` / `data-press` / `ngp*`). Do not style them.

The **Side by side** story renders both backends from one template.
