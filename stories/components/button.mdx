# Button

Triggers an action or navigates. Use the `voltButton` attribute on a native `<button>` or `<a>`, or the `<volt-button>` element.

**Stable** · Forms & Inputs · [Guide on voltui.dev](https://voltui.dev/docs/components/button)

> Recommended for production use. The public API follows the 1.x compatibility promise.

## When to use

- Submitting, confirming or starting an action: `variant="solid"` for the primary action, `outline` or `ghost` for secondary ones.
- Navigation that should look like a button: put `voltButton` on a real `<a>`, never an `<a>` around a `<button>`.
- Destructive actions: `variant="destructive"`, ideally behind a confirmation dialog.

## Installation

Install the package and import the parts you use (the full example below also shows services and types):

```bash
npm install @voltui/components
```

```ts
import { VoltButton, VoltNativeButton } from '@voltui/components';
```

Or copy the source into your project and own it: `npx @voltui/cli add button`.

## Full example

The same code as the [voltui.dev guide](https://voltui.dev/docs/components/button), as you would write it in an application:

````ts
import { Component } from '@angular/core';
import { RouterLink } from '@angular/router';
import { VoltButton, VoltNativeButton, VoltSpinner } from '@voltui/components';

@Component({
  imports: [RouterLink, VoltButton, VoltNativeButton, VoltSpinner],
  template: `
    <!-- Native element: the element you write is the one that is focused and announced -->
    <button voltButton type="submit">Save</button>
    <button voltButton variant="outline" type="button">Cancel</button>

    <!-- Links styled as buttons: a real <a>, never <a><button> -->
    <a voltButton variant="outline" routerLink="/docs">Documentation</a>
    <a voltButton variant="ghost" href="https://github.com/Andersseen/volt-ui" target="_blank" rel="noopener">
      GitHub
    </a>

    <!-- Icon-only: name it with aria-label; hide the icon -->
    <button voltButton variant="ghost" size="icon" type="button" aria-label="Switch theme">
      <svg aria-hidden="true" width="16" height="16" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2">
        <circle cx="12" cy="12" r="4" />
      </svg>
    </button>

    <!-- Loading: the text says what is happening, so the spinner is decorative -->
    <button voltButton type="button" [disabled]="saving">
      @if (saving) { <volt-spinner size="sm" /> }
      {{ saving ? 'Saving…' : 'Save' }}
    </button>

    <!-- Pending: aria-disabled keeps keyboard focus on the button (a disabled one drops it to
         <body>). Volt only dims it — it does NOT block clicks or Enter/Space, so the handler
         must guard the action itself. -->
    <button voltButton type="submit" [attr.aria-disabled]="saving ? 'true' : null" (click)="save()">
      {{ saving ? 'Saving…' : 'Save' }}
    </button>

    <!-- Blocked but explained: still focusable, so aria-describedby can say why -->
    <button voltButton variant="destructive" type="button" aria-disabled="true" aria-describedby="why">
      Delete
    </button>
    <p id="why">The last administrator cannot be deleted.</p>

    <!-- <volt-button> is still supported; ARIA inputs are forwarded to its inner <button> -->
    <volt-button variant="destructive" aria-describedby="delete-hint">Delete</volt-button>
  `,
})
export class MyComponent {
  saving = false;

  save() {
    if (this.saving) return; // aria-disabled does not do this for you
    // …
  }
}
````

## Accessibility

- The native attribute form keeps the element you wrote: the focused and announced element is a real `<button>` or `<a>`.
- Icon-only buttons (`size="icon"`) need an `aria-label`; hide the icon itself with `aria-hidden`.
- `disabled` removes the button from the tab order. `aria-disabled="true"` only dims it and keeps focus, so a pending button can stay focused and explain itself with `aria-describedby`. Volt does not block clicks on an `aria-disabled` button: guard the handler.
